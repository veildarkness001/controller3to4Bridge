## Bluetooth phase references — 2026-10-17

No external implementation code was incorporated in this phase. Protocol values and names/NIDs were checked against:

- USB Host Shield 2.0, PS3BT.cpp, commit `e5bc9950ba5389b67ad99175c312154af53df71d`: https://github.com/felis/USB_Host_Shield_2.0/blob/e5bc9950ba5389b67ad99175c312154af53df71d/PS3BT.cpp. HIDP activation `53 f4 42 03 00 00`, DATA/Input, and HID channels. Reference source with its notices retained; the implementation was not copied.
- USB Host Shield 2.0, [PS3BT.cpp](https://github.com/felis/USB_Host_Shield_2.0/blob/master/PS3BT.cpp) and [PS3Enums.h](https://github.com/felis/USB_Host_Shield_2.0/blob/master/PS3Enums.h), consulted on 2026-10-19: Bluetooth output report 1, LED mask and timing fields, motor-off values, and spacing between control commands. Protocol reference for candidate 0.12.3; no external implementation is incorporated. Native output request layout was separately checked against the locally retained firmware library. Submission success is not hardware validation of the LED state.
- BlueZ sixaxis.c, commit `fa6ba55020dee3c3183041c854c347b4582448be`: https://github.com/bluez/bluez/blob/fa6ba55020dee3c3183041c854c347b4582448be/plugins/sixaxis.c. Wired pairing research; no F5 writes were added in this phase.
- idc/ps4libdoc, 9.00 commit `a71315e7f36e312ae71e9e3a92982e9ffbfc725f`: https://github.com/idc/ps4libdoc/blob/a71315e7f36e312ae71e9e3a92982e9ffbfc725f/system/common/lib/libSceBluetoothHid.sprx.json. Symbol names and NIDs, without signatures or evidence of firmware 13.52 compatibility.
- OpenOrbis BluetoothHid.h and the SharpEmu BluetoothHidExports.cs stub: inspected for declarations; they do not provide a complete ABI validated on hardware. No implementation was copied. These functions are not called.

Reference copies are under `work/bluetooth-research/`, with a URL/commit/SHA256 manifest in `sources.json`. AF_BLUETOOTH and the HCI/L2CAP protocols come from the FreeBSD headers in the SDK already credited above; they were candidates for inspection, not assumed support.

## Native power-menu investigation — 2026-10-19

[pad2c, ps5_vpad.c](https://github.com/sub0x00001/pad2c/blob/main/src/ps5_vpad.c), GPL-3.0-or-later, was consulted for the `sceMbusDisconnectDevice(...)` and `SCE_MBUS_EVENT_DEVICE_REMOVED` log formats. Its stated hardware results concern PS5 13.60, not PS4. No implementation was copied. The optional `bluetooth-menu-probe` target only classifies events and observes remote settings; it does not interpret them as a power-off command. The 20-byte remote-setting output layout was checked independently against the locally retained PS4 13.52 library. This diagnostic retains the kernel-log reader until cleanup and always preserves the current latest build metadata.

The native menu's disconnect request for this project's own virtual device was subsequently observed on PS4 13.52 with diagnostic 0.12.4. Candidate 0.12.5 handles that exact device request; it does not infer power-off from remote-setting flags or act on another device's requests. It reuses the existing Bluetooth cleanup and verifies link absence before restarting the activation wait. One manual shutdown/reactivation cycle was then verified on the same PS4: LED off, link absent, cleanup successful, and working input after PS and user selection without reloading the payload. This does not establish repeated-cycle or broader coexistence behavior.

## Native analysis and pairing — 2026-10-18

Capstone 5.0.6 (https://github.com/capstone-engine/capstone/tree/5.0.6), BSD license and notices included in its sources/distribution: a local disassembly tool in `work/python`, not linked into the payload. Firmware 13.52 libraries and static fragments used in the research are retained only in `work/`; they are not incorporated or redistributed as product sources. The ABI and experimental operations are this project's own implementation in `src/platform/ps4/` and `include/dt/`.

For USB SET_REPORT F5, the raw eight-byte format (`01 00` followed by six host address bytes in conventional order) was checked against sixpair.c (https://github.com/lakkatv/sixpair/blob/master/sixpair.c) and USB Host Shield 2.0 BTD.cpp (https://github.com/felis/USB_Host_Shield_2.0/blob/e5bc9950ba5389b67ad99175c312154af53df71d/BTD.cpp), consulted on 2026-10-18. BlueZ sixaxis.c, already cited above, provides a reference for reversing little-endian bdaddr ordering; hidraw framing differs from raw USB control transfers. No implementation was copied. Pairing tool 0.6.0 was verified on hardware by reading back the result; restore tool 0.6.1 has only been tested locally.
